Fault Injection Testing for File Sync

Catch silent data loss in file sync tools before your users do.

SyncFault runs rclone bisync, unison, and alto inside isolated sandboxes, injects deterministic mid-transfer faults, and checks every surviving byte against an acceptable-state model.

System Architecture

How a single seed drives a reproducible crash test.

SyncFault never mocks or patches the sync tool under test. It mutates real files on disk, kills real process groups, and checks only the final filesystem state.

01. SCENARIO + SEED
PCG Stream Expansion

A YAML recipe expands into a deterministic sequence of file creates, edits, renames, and sync cycles via a single math/rand/v2 stream.

02. JOURNAL TAP
Operation-Index Fault

Every syscall logs pre and post SHA-256 digests to an O_SYNC JSONL journal. At op_index: N, the armed injector fires immediately.

03. QUIESCENCE
Heal & Recovery Loop

Faults heal and the sync tool restarts. SyncFault runs recovery cycles until two consecutive cycles produce zero file changes across replicas.

04. ORACLE VERDICT
State Classification

The Oracle computes acceptable end states from the journal alone and walks sideA, sideB, and remote to emit a verdict.

Engineering Design

Every reported bug is reproducible from a seed.

01 / DETERMINISM

Operation-Anchored Faults

Wall-clock timers make crash tests hard to reproduce. SyncFault anchors sigkill, netcut, netslow, and enospc to exact operation counts in the run journal, so every finding can be re-run with syncfault replay --run-id.

02 / VERIFICATION

Acceptable-State Oracle

When a crash interrupts a rename or concurrent edit, more than one end state can be valid. The Oracle computes the set of acceptable post-recovery states from the journal alone, without reading target logs.

03 / SELF-VALIDATION

Built-In Reference Gate

SyncFault includes refgood (atomic temp-write and fsync reference sync) and refbad (sabotaged non-atomic rename and torn write). CI requires syncfault selfcheck to catch refbad 10/10 times on every commit.

Quickstart

Compile in two seconds. Run your first fault suite.

SyncFault compiles to a single static Go binary with zero external dependencies. Scenarios are plain YAML files, so you can add new fault coverage without editing Go code.

doctor Check namespaces, tools & sweep orphans
selfcheck Verify refgood (CLEAN) & refbad (caught)
run / replay Execute or deterministically replay a seed
suite / report Run matrix & build scorecard.md + index.html
Terminal: Build & Run
git clone https://github.com/Vishv07/syncfault.git
cd syncfault
go build -o syncfault ./cmd/syncfault

# 1. Check host capabilities and run the self-validation gate
./syncfault doctor
./syncfault selfcheck

# 2. Execute the smoke suite and generate the scorecard
./syncfault suite --adapter refgood --suite smoke --db runs.db
./syncfault report --db runs.db --out report/
scenarios/rename_storm_sigkill.yaml
name: rename_storm_sigkill
workload:
  recipe: rename_storm
  params:
    depth: 4
    files: 24
    file_size: { min: 1KiB, max: 64KiB }
  sides: [A]
fault:
  type: sigkill
  at:
    op_index: 12
    jitter_ms: { min: 0, max: 20, seeded: true }
runs:
  seeds: [1..50]
  timeout_s: 180
Technical FAQ

Safety rails, privileges, and extensibility.

Can a fault run accidentally touch my real files or live cloud remotes?

No. Every workload and verification path passes through sandbox.ResolveAndConfine, which evaluates symlinks and aborts immediately (ErrPathEscape) if any path resolves outside $XDG_RUNTIME_DIR/syncfault/<run_id>/. Adapters generate sandbox-local configs and never read ~/.config/rclone.

Does SyncFault require root access or a custom kernel?

No. On Linux, network and mount injectors use unprivileged user namespaces (unshare -rn). On macOS or hosts where user namespaces are disabled, syncfault doctor detects the environment and runs in rootless sigkill and sandbox quota mode automatically.

How much code does it take to test my own sync engine?

Around 150 lines of Go implementing the 8-method adapter.Target interface (Setup, SyncCycle, PID, Teardown, ConflictPolicy). Your adapter immediately works with all 7 workload recipes, 4 fault injectors, the replay engine, and HTML/Markdown scorecard generation.
